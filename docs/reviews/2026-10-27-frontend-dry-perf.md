# Frontend review: DRY and performance (Korpus Builder)

Scope: `frontend/src/App.svelte` (6,335 lines; 4,837 of them script), `components/*.svelte`, `lib/api.js`, `lib/tableColumns.js`, `app.css` (5,583 lines), `vite.config.js`. Read-only review of the worktree at `eb15bc5`.

Summary: the newer pieces (refresh scheduler, boot parallelisation, request tokens, ThreeGraph lifecycle, column defs) are careful work. Most of the cost is in two areas. First, App.svelte is one 6k-line component that holds three parallel implementations of "what does tab X need", two unreachable tabs, and 36 copies of the 401 handler. Second, the hot paths (seed table selection, the 2 s corpus poll, the log stream) do O(n) or O(n²) work on every tick. The findings are ranked below: **12 Important, 16 Minor**.

Cadences used below: the active poll runs every 2 s (search running, worker batch in flight, or non-admin with live leases). The idle poll runs every 20 s (workspace, dashboard or downloads tab visible).

## Important

### 1. The seed candidate table is torn down and rebuilt on every checkbox click, and the selection check is O(rows × selected)
- `App.svelte:5350, 5392, 5434, 5466`: four `{#key `${sourceId}:…:${selectionVersion}`}` blocks wrap the select-all checkbox, the summary actions, the toolbar and **the whole candidate table**. `seedSelectionVersions[sourceId]` is bumped by every toggle, clear and select-all (`3196–3230`, 4 copies of the bump). So one checkbox click destroys and recreates every row × every column. With "Show more" a table holds up to 2,000 rows × 8–10 cells.
- Each row calls `isSeedCandidateSelected` twice (`5487`, `5508`). That function does `getSeedSelectionForSource(source).includes(key)` on an array (`3164`). With 2,000 rows and select-all, one render is about 8M string compares, on top of the rebuild.
- `seedCellText` runs twice per cell (once for `title=`, once for the content, `5545`). Authors cells run `formatAuthors` and `formatAuthorsShort`, and the second one parses JSON again (`779–818`).
- The `{#key}` hack and the "pass `seedSorts` in so Svelte tracks it" comments (`2884`, `3083`) look like Svelte 4 reasoning. Under Svelte 5 (also in legacy mode), component `let`s are signals, and template effects track reads made inside called functions at runtime. **Verify by removing the four `{#key}` blocks and running `seed-upload.spec.ts` / `app.spec.ts`.**
- **Refactor:** store selections as `Set`s (`seedSelections: Record<sourceId, Set<string>>`, replaced immutably), or derive `$: selectedKeySet = new Set(seedSelections[expandedSeedSourceId] || [])` once per expanded seed. Drop `seedSelectionVersions` and the `{#key}` blocks. In the row, compute `{@const checked = selectedKeySet.has(candidate.candidate_key)}` once and `{@const text = seedCellText(candidate, column.key)}` once per cell.

### 2. The live poll re-fetches and re-renders the entire loaded corpus every cycle
- `runLiveRefreshCycleOnce` (`1634`) calls `loadCorpus({ preserveSelection: true, quiet: true })` on every cycle. Its `requestedLimit` (`4069`) is `max(120, corpusItems.length)`. A user who scrolled to 3,000 rows makes the backend serialise 3,000 rows every 2 s (active) or 20 s (idle). The `/api/corpus` route (`backend/src/app.js:5576`) does not clamp `limit`.
- Every row is rebuilt with `normalizeCorpusItem` (spread plus `formatAuthors`, which may `JSON.parse`) and assigned unconditionally. Every keyed row in `Corpus.svelte` then gets a new object, so every cell effect re-runs. `cellText` is called twice per cell (`Corpus.svelte` title attribute plus content), and the authors cell splits and re-joins strings.
- **Dead work on the same path:** `App.svelte:448–451` defines `rawItems / metaItems / downloadedItems / failedItems`. These are four full `filter` passes over `corpusItems` on every reload, and **none of them is read anywhere**.
- **Refactor:** (a) delete the four dead `$:` filters. (b) Make the poll refresh only page 1, or only the stage totals, and keep appended pages until the user acts. Alternatively send `ids=` for the loaded rows, or use `If-None-Match`/`updated_since`. (c) Skip the assignment when nothing changed, using a cheap signature such as `total + stageTotals + first/last id`. (d) In `Corpus.svelte`, compute `{@const text = cellText(...)}` once per cell, and store a precomputed `authors_short` in `normalizeCorpusItem`.

### 3. Redundant requests on every refresh cycle
For an admin on the workspace during the active cadence, each 2 s cycle fires ingest stats, corpus, OpenAlex quota, seed sources, `/api/downloads`, `/api/downloads/worker/status` and `/api/pipeline/daemon/status`. That is **7 requests every 2 s; 4 are needed.**
- `loadDownloadWorkerStatus` (`4146`) and `loadPipelineWorkerStatus` (`4162`) both run in every cycle and tab refresh. The backend `/api/downloads/worker/status` (`backend/src/app.js:6458`) calls the same `readPipelineDaemonStatus()` and `readWorkerBacklogSummary()` as `/api/pipeline/daemon/status` (`6192`). `loadPipelineWorkerStatus` already writes `downloadWorker` from that payload. The two responses also race to write `downloadWorker`. **Drop `loadDownloadWorkerStatus` from all 6 refresh call sites** and keep it only for the explicit worker buttons, or remove it entirely.
- `loadDownloads()` (200 rows) runs in every cycle for admins (`1690`), but only the Downloads tab and the Dashboard's `recentDownloads` render it. Gate it on `activeTab in {downloads, dashboard}`.
- `loadOpenAlexQuota()` runs every cycle (`1683`). The quota only changes when the backend talks to OpenAlex. Refresh it after search, promote or preview, plus at the idle cadence or while a search run is active.
- `refreshAll` always runs `loadKantroposAssignment()` (`1963`). That call can trigger `loadKantroposTargets()` first, which is 2 requests on every boot, corpus switch, create and delete. Only the Korpus Management tab displays it. It also races with `loadUpstreamBrowse`, which runs `loadKantroposTargets()` again when `kantroposTargets.length === 0` (`2180`, `2265`). Move it into the upstream tab loader, behind one shared in-flight promise.

### 4. The log stream copies a 5,000-element array per WebSocket line, on every tab
- `App.svelte:4636`: `logs = [...logs, line].slice(-maxLogHistory)` runs for every pipeline log line, whatever tab is active (the `Logs` component is only mounted on `#/logs`). During a worker burst of tens of lines per second, that means about 10⁵ element copies per second plus a reactive invalidation each time.
- `Logs.svelte` renders `{#each logs as entry}` **unkeyed** over up to 5,000 lines. Once the buffer is full, every new line shifts all rows, so up to 5,000 text-node updates per line.
- Each JSON frame is parsed twice: `parsePromotionEventMessage` and then `parseExtractionEventMessage` (`933`, `955`, called at `4584–4589`).
- **Refactor:** collect incoming lines in a plain (non-reactive) array and flush them into `logs` once per `requestAnimationFrame` (or every 250 ms), and only while `activeTab === 'logs'`. On other tabs, keep a ring buffer and assign it when the tab opens. Parse JSON once in `onmessage`: `const msg = tryParseJson(event.data)`, then dispatch on `msg.kind`. In `Logs.svelte`, key by a monotonically increasing sequence number, or render the box as one `<pre>` text node.

### 5. The refresh "plan" is encoded three times, and the shared in-flight flag silently drops tab-switch refreshes (bug)
- "Which resources does tab X need?" lives in `startWorkspaceLoads`/`refreshAll` (`1947–1980`), `refreshForActiveTab` (`1701–1740`), and both branches of `runLiveRefreshCycleOnce` (`1634–1699`). Those two branches duplicate the `if (pipelineRefreshInFlight) { if (dirty) refreshDirty = true; return }` guard. `refreshReason` and `shouldRunLiveRefresh` both carry the `diagnosticsEnabled && (workerBusy(pipelineWorker) || workerBusy(downloadWorker))` check, and `tabNeedsWorkspaceData` and `shouldRunLiveRefresh` both carry the `workspace|dashboard|downloads` list.
- **Bug:** `refreshForActiveTab` returns early when `pipelineRefreshInFlight` is set (`1706`) or when the last tab refresh was under 800 ms ago (`1705`). For `#/upstream`, that call is the only place `loadUpstreamBrowse` runs automatically (`1730`). Switching to Korpus Management while a poll cycle is in flight, or within 800 ms of the previous switch, leaves the tab empty until the user clicks Refresh.
- `onFocusOrVisible` is bound to both `focus` and `visibilitychange` (`4798–4799`). Returning to the tab fires both, and every alt-tab back to the window triggers a full tab refresh outside the cadence. The 800 ms guard only hides the duplicate.
- **Refactor:** add one table, `const TAB_RESOURCES = { workspace: ['stats','corpus','seeds'], dashboard: [...], downloads: [...], upstream: ['upstream'], graph: [] }`, plus `ADMIN_RESOURCES`. Add a `loaders` map from resource name to load function, and `refreshResources(names)` that dedupes **per resource** through a `Map<name, Promise>` of in-flight loads instead of one global boolean. Boot, tab switch and cycle then become `refreshResources(resourcesFor(tab, { dirty, admin }))`. Keep the scheduler (`refreshReason`/`scheduleRefresh`) as it is; it is the clean part.

Their script support is also dead: `latestSelection` and the four `$:` derivations (`240–259`), `toggleLatestSelection`, `selectAllLatest`, `enqueueSelectedLatest`, `processMarkedBatch` (`2526–2610`), `handleToggleLatestRun`, `loadLatestEntries` (a 180 s polling loop), the `searchResults`/`searchQueueConfigs`/`searchSelection` machinery including `$: allSearchSelected` and `selectedSearchCount` (`348–357`), `initializeSearchQueueConfig`, and `enqueueSelectedSearchResults` (`3951`, not referenced even by the dead tab).
- **Stale test:** `tests/pipeline-perf.real-pdf.spec.ts:179` clicks `tab-ingest`, which no longer exists.
- **Promotion animation subsystem:** `queuePromotionAnimation` and `flushPromotionAnimations` return unless `activeTab === 'corpus'`, which can never happen because `normalizeTab` maps `corpus` to `workspace`. The dead code is `corpusRowElements`, `bindCorpusRow` (never used as an action), `playPromotionAnimation`, the promotion highlights, `isPromotionHighlighted` (unused), and the `.promotion-slide` / `.promotion-target-flash` CSS (~150 lines). The backend still pushes promotion frames that the client parses and throws away.
- **Scroll preservation is a no-op:** `rawCorpusTableEl`, `metaCorpusTableEl` and `downloadedCorpusTableEl` are never bound with `bind:this`, so `snapshotCorpusScroll`/`restoreCorpusScroll` (`1594–1607`) do nothing.
- **Unused helpers:** `formatPipelineStatus`, `pipelineStatusLabel`/`Tone`/`Title` (`879–907`), `buildDegreeMap` and `clamp` (`4692–4706`), and the four `rawItems…` filters (finding 2).
- On extraction finish, `finalizeExtractionAfterBackendCompletion` fetches `fetchBibliographyEntries` into `latestEntries`. Only the dead ingest tab renders that list, so it is one wasted request per extraction.
- **CSS:** about 55 class selectors in `app.css` match nothing in any `.svelte` file. This excludes dynamically built names such as `openalex-quota-pill--*` and `seed-run-status--*`. Examples: the whole `header-pipeline*`, `header-log-stream*`, `header-invite`, `header-corpus-*`, `workspace-selection-strip*`, `ingest-job-progress*`, `ingest-start-prompt*`, `search-queue-*`, `search-row-*`, `cols-4/5/7`, `cols-corpus-*`, `corpus-virtual-spacer`, `corpus-details*` and `graph-layout`/`graph-wrap` families. In addition, 24 top-level selectors are defined twice (e.g. `.header-corpus`, `.logout-button`, `.short-input` 3×).
- **Action:** delete them. The tab markup alone is about 400 lines, and deleting it also removes about 15 `$:` statements and functions from the reactive graph.

### 7. The 401 handling block is copied 36 times, and it is incomplete
- `if (error?.status === 401) { authStatus = 'unauthenticated'; setAuthToken(''); return }` appears 36 times in `App.svelte`, with 38 assignments of `authStatus = 'unauthenticated'`.
- It does not do what `handleLogout` does: it neither runs `disconnectLogs()` nor `resetFrontendState()`. After a token expires, the WebSocket stays open and keeps appending lines. The previous user's seed candidates and uploads stay in memory and can show up after a different user signs in, because `refreshAll` does not reset `seedCandidatesBySource` and similar state.
- **Refactor:** in `api.js`, add `export function onUnauthorized(handler)`. `throwIfUnauthorized` (or the new `requestJson` from finding 8) calls the handler before throwing. App registers one `expireSession()`, which runs the `handleLogout` path. The 36 catch blocks shrink to `if (error?.status === 401) return` or disappear entirely.

### 8. api.js repeats the same request boilerplate 56 times, with inconsistent 401 tagging and error format
- The `fetchWithTimeout → await throwIfUnauthorized(response) → if (!response.ok) { const payload = await response.text(); throw new Error(payload || '…') } → return response.json()` sequence appears 56 times across 64 exported functions.
- Five functions skip `throwIfUnauthorized`: `fetchMe`, `fetchCorpora`, `selectCorpus`, `createCorpus` and `shareCorpus`. With an expired token, `handleSelectCorpus` therefore shows a raw `{"error":"Unauthorized"}` text instead of logging out.
- Error messages are raw response bodies, usually JSON. App unwraps them with `JSON.parse(message)` in two places (`2556`, `2600`), and the rest show raw JSON.
- `fetchDownloadQueue` (`api.js:812`) and `runKeywordSearch` (default `fallbackToSample = true`) silently return **sample data** on any error, including an 8 s timeout. Under backend load, the admin Downloads table can show fabricated rows (see Minor 2).
- **Refactor:** `async function requestJson(path, { method = 'GET', body, timeout = DEFAULT_TIMEOUT, error = 'Request failed', raw = false } = {})`. It sets the JSON headers, tags 401s, parses `{error}` bodies into `Error.message`, and returns `response.json()` (or the `Response` when `raw` is set, for blob downloads). Most exports become one-liners, and the file shrinks from about 1,190 lines to about 450.

### 9. Status, label, author and table logic is duplicated across App, Corpus and UpstreamBrowser
- `seedCandidateState` (`2753`) and `latestIngestState` (`2462`) are identical, including the same 10-state whitelist.
- `SEED_METADATA_LABELS`/`SEED_DOWNLOAD_LABELS` (`App 2998–3012`) are the same tables as `METADATA_LABELS`/`DOWNLOAD_LABELS` in `Corpus.svelte`. `RAW_STATUSES` and the failed-status sets are defined in both files. `formatPipelineStatus` (App, dead) and `itemStageLabel` (Corpus) map the same statuses to labels.
- `seedCellText` (`3048`, 15 cases) and `Corpus.svelte` `cellText` (15 cases) are the same switch except for the `'-'` vs `''` defaults and 3 keys. `corpusSortIndicator`/`seedSortIndicator` and `toggleCorpusSort`/`toggleSeedSort` implement the same asc/desc toggle.
- The seed row and the corpus row duplicate the same keyboard handler (`if (e.key === 'Enter' || e.key === ' ') { if (tagName is INPUT/BUTTON/A) return; … }`). They also duplicate the inline detail card (Year, Author, Source, DOI and OpenAlex chips).
- There are three author parsers with different rules: `formatAuthors`, `formatAuthorsList` (splits on `,`) and `parseAuthorsValue` (splits on `;`), at `779–856`. `Corpus.svelte` `corpusItemAuthors` re-splits the already joined `authors_display` on `,`. That is a **bug** for "Last, First" names: `["Smith, J.", "Doe, A."]` becomes 4 parts and renders as "Smith, J., Doe et al.". `UpstreamBrowser.itemAuthors` duplicates `Corpus.corpusItemAuthorsFull`.
- **Refactor:** create `lib/works.js` exporting `workState()`, `METADATA_LABELS`, `DOWNLOAD_LABELS`, `metadataLabel(item)`, `downloadLabel(item)`, `parseAuthors(value) → string[]` (one rule), `cellText(item, key, { blank })`, `sortIndicator(sort, column)` and `nextSort(sort, column)`. `normalizeCorpusItem`/`normalizeUpstreamBrowseItem` store `authors_list`, `authors_display` and `authors_short` once at load. Add a `WorkDetailCard.svelte` for the inline detail card, and later a `WorkTable.svelte` (header plus rows plus selection column) shared by the seed and corpus tables.

### 10. Session and post-action flows are copy-pasted
- **Enter session** appears 4 times: `bootstrapAuth`, `handleLogin` (`1779`), `handleAcceptInvite` (`1823`) and `handleResetPassword` (`1864`). Each does `fetchMe → assign authUser/corpora/currentCorpusId → authenticated → loadRecursionConfig → refreshAll → connectLogs → setActiveTab if the navigation revision is unchanged`. The three handler copies run `loadRecursionConfig` and `refreshAll` **sequentially** and call `fetchMe` again right after `login()` already returned the user. Bootstrap runs the same calls in parallel.
- `handleAcceptInvite` and `handleResetPassword` are line-for-line identical apart from the API call and the error text. The same is true of their forms (`4845–4881`). The `authInfo`/`authError` block is repeated in all 4 forms.
- **Corpus change** appears 3 times (`handleSelectCorpus`, `handleCreateCorpus`, `handleDeleteCorpus`): `fetchMe → assign → resetFrontendState → refreshAll → if pipeline logs, handleLogsCorpusFilterChange`.
- **After promote** appears 2 times: `promoteSeedCandidateKeys` (`3460`) and `handlePromoteWholeSeedSource` (`3536`) share about 30 lines (refresh tasks, reload the refreshed source, `seedPromotionStatus`, the 401 path, then `finally { busy = false; loadOpenAlexQuota() }`).
- **Extraction done** appears 2 times: the log-regex path (`1446–1475`) and the WS `extraction` event (`4598–4625`) both run `updateUploadByBackendFilename` → `updateExtractionProgress(...)` → finalize or finish. The "Finalizing extracted entries… 98%" update is written out 4 times. The empty `extractionProgress` object is written 3 times.
- **Refactor:** `enterSession(me, { landingTab, preserveAuthFlow })`, `reloadForCorpus(me, fallbackId)`, `afterPromotion(source, result, count)`, `handleExtractionDone({ filename, baseName, status })`, `const EMPTY_EXTRACTION = Object.freeze({...})`, and an `AuthPasswordForm.svelte` with props `title, submitLabel, onSubmit`.

### 11. Bug: the admin Dashboard's "global overview" always shows zeros
- `Dashboard.svelte` renders `globalStats` and `globalBacklog` when `showGlobalOverview={isAdmin}`. App passes `globalIngestStats` and `globalWorkerBacklog`, but nothing ever calls `loadIngestStats({ global: true })` or `loadPipelineWorkerStatus({ global: true })`. The `global` branches at `2731` and `4166` are unreachable.
- **Fix:** add both to the dashboard resources in the finding-5 table (admin only), or remove the section.

### 12. Bug: expanding a paged seed overwrites its item count with the page size
- `reconcileSeedSourceCandidates` (`2809–2843`) sets `candidate_count: nextCandidates.length` and recomputes `state_counts` from **the loaded page only**. Expanding a 70,000-item search seed changes the pill to "200 items" and "To review: 200" until the next seed-list poll (up to 20 s idle). In the meantime, `estimatedSelectableSeedCount` (`3140`) reads the page-local `state_counts` for the "Promote all" and "select all" counts.
- **Fix:** only overwrite these fields when `nextCandidates.length >= payload.total` (the seed is fully loaded). Otherwise keep the server's `candidate_count` and `state_counts`, or use `payload.source_summary` when it is present.

## Minor

1. **The Corpus stage filter only applies to the loaded page** (`Corpus.svelte` `filteredItems`), while the counts in the dropdown are server totals. "Downloaded (5,000)" can show 3 rows, and infinite scroll may not trigger because the filtered list is too short. Make `stage` a server parameter, as `q` already is.
2. **The sample-data fallback** in `fetchDownloadQueue` (and the default `fallbackToSample = true` in `runKeywordSearch`) can show fake rows in production. It also ships `sample-data.js` in the main bundle. Remove it, or gate it behind `import.meta.env.DEV`.
3. **`sortSeedCandidates` runs inside the `{#each seedSources}` `{@const}`** (`5324`) for every seed, including collapsed seeds whose candidates are still cached. Each `seedSources` poll re-sorts PDF seeds with `localeCompare` plus label accessors. Memoise per `sourceId` on `(candidates array ref, sort)`.
4. **`estimatedSelectableSeedCount(source)`** is evaluated 5 times per seed summary per render (`5352–5400`). Once a seed is fully loaded, each call walks all candidates (`selectableSeedCount`). Compute it once with `{@const}`.
5. **Blob and URL download snippets** (createElement('a'), click, revoke) appear 6 times: App ×4 (`handleExportDownload`, `handleDownloadSeedDocument`, `handleSeedCandidateFile`, `handleDownloadedCorpusFile`), `ScraperLab.downloadMetadataDraft` and `UpstreamBrowser.downloadCurrentItem`. Add `lib/download.js` with `saveBlob(blob, filename)` and `openUrl(url)`.
6. **Seed-selection bookkeeping repeats:** `Object.fromEntries(Object.entries(seedSelections).filter(...))` appears 4 times, the `seedSelectionVersions` bump 4 times, and the "selectable keys of loaded candidates" pipeline 3 times (`3192`, `3218`, `3388`). This goes away with finding 1. `latestSelectionKey` and `searchResultKey` are near-duplicates (and dead, see finding 6).
7. **Static imports of heavy tab components:** `ThreeGraph.svelte` (2.1k lines), `ScraperLab` and `UpstreamBrowser` are imported statically into the main chunk. `three` itself is already lazy (`ThreeGraph.svelte:1645`), which is good. Load the tab components with `{#await import('./components/ThreeGraph.svelte')}` or a small `LazyTab` wrapper.
8. **`finalizeExtractionAfterBackendCompletion`** awaits `loadSeedSources → focusSeedSource → loadIngestStats → loadIngestRuns` sequentially (`1276–1280`). `focusSeedSource` may call `loadSeedSources` again. Run the independent ones with `Promise.all`.
9. **`resetFrontendState`** (`1985`) misses `seedSorts`, `seedSelectionVersions`, `selectedSeedCandidateKeys`, `startedSearchRunIds`, `corpusHasMore` and `corpusFilterQuery`/`seedFilterQuery`. It also sets `corpusStageTotals` without the two `failed_*` keys that the rest of the code expects. Build the state from one `initialWorkspaceState()` factory instead of hand-listing about 50 assignments.
10. **`persistStoredUploads`** serialises to localStorage on every `updateUpload`. It and `pruneExtractedUploads` both rebuild `extractedBaseNames` from `ingestRuns`. Derive the set once with `$:`.
11. **`UpstreamBrowser`** filters both lists on every keystroke without a debounce. `itemMatchesFilter` lowercases title, authors and source corpora for every item on each run. Precompute a lowercase `search_blob` in `normalizeUpstreamBrowseItem`. The cost is small at a few hundred rows, and the approach is inconsistent with the server-side filter used for Corpus.
12. **`rearmRefreshOnChange(authStatus, anySearchRunning, ingestStats, pipelineWorker, downloadWorker)`** (`213`) re-arms on 3–4 object reassignments per cycle. It is cheap because `scheduleRefresh` keeps an earlier timer, but `activeTab` and `isAdmin` are missing from the list and rely on `setActiveTab` calling `scheduleRefresh` by hand. List them explicitly, or use a `$:` on `refreshReason()`'s inputs and a reason string.
13. **The worker status objects** in `loadPipelineWorkerStatus` (`4174–4194`) rebuild the same `{running, in_flight, started_at, last_tick_at, last_result, last_error}` shape twice. They also re-implement the backend mapping, and `JSON.stringify(details)` builds an error string that is only shown as text. Use `toWorkerView(workerHeartbeat)`.
14. **`app.css`** defines 24 top-level selectors twice, some as accidental overrides (`.header-corpus*` family, `.app-shell .subtitle`, `.short-input` 3×). Merge them while deleting the dead families from finding 6.
15. **`vite.config.js`** sets `watch.usePolling: true` unconditionally. That is a constant CPU cost in the dev container and is only needed on some bind mounts. Gate it on an env var.
16. **`handleSelectCorpus` and similar handlers** write errors into `authError`, which is only rendered on the login screen. Inside the app these failures are invisible; use `corpusActionStatus`.

## What is already good
- **Refresh scheduler core** (`refreshReason` / `scheduleRefresh` / `requestRefreshSoon`): it keeps a single timer, and an earlier-due timer is never pushed back. Hidden tabs do not poll but remember a dirty flag. Log bursts coalesce into one trailing run, and a dirty flag set during an in-flight cycle gets its trailing run. `refresh-scheduler.spec.ts` covers this well. The problems are in *what* each cycle loads (findings 3 and 5), not in *when* it runs.
- **Boot parallelisation:** `startWorkspaceLoads()` before `fetchMe()` is correct because the backend scopes requests by token. The loads are passed into `refreshAll` so nothing is fetched twice, and `boot-requests.spec.ts` pins exactly one request per resource. Graph and other non-workspace landing tabs skip workspace data.
- **Race safety:** monotonic request tokens on seed list, seed candidates, corpus, upstream browse and Kantropos assignment. Append dedupe by `candidate_key`. The `seedAppending` double-click guard. `startedSearchRunIds` with a miss limit.
- **Server-side paging, sorting and filtering** for seeds and corpus, and a 300 ms debounce on both filter inputs. The background seed reload passes `lightSummary`.
- **ThreeGraph:** `three` and OrbitControls load dynamically. Edge buffers are built in a Worker with a synchronous fallback. Rendering is on-demand with `requestRender` and settle frames, not a perpetual rAF loop. `onDestroy` tears down every listener, rAF handle, observer, GPU object and the worker, and resolves pending builds. Node and cluster details are cached.
- **`tableColumns.js`:** one column definition list with per-table visibility, a safe localStorage merge, and an all-hidden fallback. This is the right model to extend into the shared table in finding 9.
- **Listener hygiene in App:** `onMount` removes everything it adds (hashchange, focus, visibility, media query, WS, timers). ScraperLab clears its interval. ColumnPicker uses `svelte:window`.
